# ที่มาของข้อมูลและข้อจำกัด

## ข้อมูลในคลังความรู้มาจากไหน

เนื้อหาใน `data/` เรียบเรียงจากองค์ความรู้ทางโรคพืชและการจัดการแตงโมที่เป็นที่ยอมรับทั่วไป
โดยอ้างอิงกรอบจากแหล่งต่อไปนี้ (รายการเต็มพร้อมลิงก์อยู่ใน `data/sources.json`)

| ประเภท | แหล่ง |
|---|---|
| หน่วยงานไทย | กรมวิชาการเกษตร, กรมส่งเสริมการเกษตร, กรมพัฒนาที่ดิน |
| สถาบันการศึกษา | มหาวิทยาลัยเกษตรศาสตร์ (ภาควิชาโรคพืชและคณะเกษตร) |
| สากล | American Phytopathological Society (APS), FRAC, IRAC, ISTA |
| หลังการเก็บเกี่ยว | ศูนย์นวัตกรรมเทคโนโลยีหลังการเก็บเกี่ยว |

**สิ่งที่ต้องเข้าใจให้ตรงกัน:** ข้อมูลนี้เป็นการเรียบเรียงเพื่อการศึกษาและใช้เป็นแนวทาง
ไม่ได้คัดลอกตัวเลขมาจากเอกสารฉบับใดฉบับหนึ่งแบบคำต่อคำ และไม่ใช่เอกสารทางการของหน่วยงานใด
ก่อนนำไปใช้ในเชิงพาณิชย์หรือเผยแพร่ต่อ ควรตรวจสอบกับเอกสารต้นทางฉบับล่าสุด

## เรื่องที่ต้องตรวจสอบซ้ำเสมอ

### 1. สถานะการขึ้นทะเบียนของสาร

รายการวัตถุอันตรายทางการเกษตรที่อนุญาตให้ใช้ในไทยเปลี่ยนแปลงได้ ตัวอย่างที่สำคัญ
คือประเทศไทยยกเลิกการใช้พาราควอต คลอร์ไพริฟอส และคลอร์ไพริฟอส-เมทิล
ตั้งแต่ 1 มิถุนายน 2563 และยังมีสารอื่นที่มีข้อจำกัดการใช้เฉพาะ

**ต้องตรวจสอบกับกรมวิชาการเกษตร (<https://www.doa.go.th>) ก่อนซื้อและใช้ทุกครั้ง**
ระบบมีหมายเหตุเรื่องนี้ไว้ที่ `data/pesticides.json` ในฟิลด์ `banned_or_restricted_th`
และแสดงบนหน้าเว็บในหน้าคลังยา

### 2. อัตราการใช้

อัตราในระบบระบุเป็น "ต่อน้ำ 20 ลิตร" ซึ่งเป็นหน่วยที่เกษตรกรไทยใช้จริง
แต่ความเข้มข้นของผลิตภัณฑ์แต่ละยี่ห้อต่างกัน เช่น อะบาเมกติน 1.8% EC กับ 3.6% EC
ใช้อัตราไม่เท่ากัน **ฉลากบนขวดที่ซื้อมาคือข้อมูลที่ถูกต้องที่สุดเสมอ**

### 3. ชื่อการค้า

ฟิลด์ `trade_examples` เป็นเพียงตัวอย่างเพื่อช่วยให้สื่อสารกับร้านค้าได้ง่ายขึ้น
ไม่ใช่การแนะนำหรือรับรองผลิตภัณฑ์ใด และชื่อการค้าหนึ่งอาจมีสารออกฤทธิ์ต่างกันในแต่ละประเทศ
**ให้ยึดชื่อสามัญของสารออกฤทธิ์ (active ingredient) บนฉลากเป็นหลัก**

### 4. ระยะเก็บเกี่ยวปลอดภัย (PHI)

ค่า `phi_days` ในระบบเป็นค่าทั่วไปของสารนั้น ค่าจริงขึ้นกับพืช อัตรา และข้อกำหนดของ
ตลาดปลายทาง ตลาดส่งออกบางแห่งกำหนดค่าตกค้างสูงสุด (MRL) ที่เข้มกว่าในประเทศ

## ข้อจำกัดของการวินิจฉัยจากภาพ

| ข้อจำกัด | ผลกระทบ | สิ่งที่ระบบทำ |
|---|---|---|
| โรคไวรัสหลายชนิดมีอาการคล้ายกันมาก | WMV, ZYMV, PRSV-W และ CMV แยกด้วยตาไม่ได้ | รวมเป็นกลุ่ม "ใบด่าง" และระบุว่าต้องตรวจ ELISA หรือ PCR เพื่อยืนยันชนิด |
| โรคทางรากมองจากใบไม่เห็น | ไส้เดือนฝอยรากปมและโรคเหี่ยววินิจฉัยผิดได้ง่าย | ใส่ไว้ใน `need_more_checks` ว่าต้องขุดรากหรือตัดเถาดูท่อลำเลียง |
| อาการบางอย่างอยู่ใต้ใบ | ราน้ำค้าง ไรแดง และแมลงหวี่ขาวอยู่ใต้ใบ | เตือนให้ถ่ายใต้ใบเพิ่ม และระบุไว้ในคำแนะนำการถ่ายภาพ |
| คุณภาพภาพมีผลมาก | ภาพมืด เบลอ หรือไกลเกินไปทำให้วิเคราะห์ผิด | ประเมินคุณภาพภาพและแจ้งปัญหาพร้อมวิธีแก้ |
| โรคหลายชนิดเกิดพร้อมกันได้ | การสรุปเพียงโรคเดียวอาจทำให้พลาด | แสดงได้สูงสุด 4 สาเหตุพร้อมคะแนน และเตือนเมื่อสองอันดับแรกคะแนนใกล้กัน |

## ชุดข้อมูลภาพสำหรับเทรนโมเดล

ยังไม่มีชุดข้อมูลภาพโรคแตงโมมาตรฐานที่เปิดให้ดาวน์โหลดได้อย่างเสถียร
`scripts/fetch_data.py` จึงรองรับสองแนวทาง

1. **ชุดข้อมูลโรคพืชทั่วไปสำหรับ pretrain** — PlantDoc (ภาพถ่ายในแปลงจริง)
   และ PlantVillage (ภาพในห้องปฏิบัติการ) ทั้งสองชุดไม่มีคลาสแตงโมโดยตรง
   แต่ช่วยให้โมเดลเรียนรู้ลักษณะทั่วไปของแผลโรคพืชก่อน

2. **ชุดข้อมูลของผู้ใช้เอง** — ซึ่งเป็นวิธีที่ได้ผลดีที่สุดในทางปฏิบัติ
   เก็บภาพจากแปลงของตนเองอย่างน้อย 100-200 ภาพต่อโรค ถ่ายหลายมุม หลายช่วงเวลา
   และหลายระดับความรุนแรง แล้วจัดโฟลเดอร์ตามรหัสโรคในคลังความรู้

ใช้ `python3 scripts/fetch_data.py search` เพื่อดูแหล่งค้นหาชุดข้อมูลเพิ่มเติม
และ `python3 scripts/fetch_data.py verify` เพื่อตรวจว่าเครือข่ายของเครื่องเข้าถึงแหล่งใดได้บ้าง
(บางเครือข่ายองค์กรบล็อก Kaggle, Hugging Face และ Zenodo ซึ่งสคริปต์จะรายงานให้ทราบ)

**ตรวจสัญญาอนุญาตของทุกชุดข้อมูลก่อนนำไปใช้** โดยเฉพาะหากจะใช้ในเชิงพาณิชย์

## การแก้ไขข้อมูล

เมื่อพบว่าข้อมูลใดไม่ถูกต้องหรือล้าสมัย

1. แก้ไขไฟล์ JSON ที่เกี่ยวข้องใน `data/`
2. รัน `python3 scripts/validate_data.py` เพื่อตรวจความถูกต้องและการอ้างอิงข้ามไฟล์
3. รัน `python3 -m pytest tests -q` เพื่อตรวจว่าไม่กระทบส่วนอื่น
4. commit พร้อมระบุแหล่งอ้างอิงที่ใช้ในการแก้ไข เพื่อให้ตรวจสอบย้อนหลังได้

การเก็บข้อมูลไว้ในไฟล์ที่อยู่ภายใต้ git ทำให้ทุกการเปลี่ยนแปลงมีประวัติว่าใครแก้ เมื่อไร และเพราะอะไร
ซึ่งสำคัญมากสำหรับข้อมูลที่มีผลต่อความปลอดภัยของผู้ใช้และผู้บริโภค


## การวัดผลโหมดออฟไลน์ด้วยภาพจริง

โหมดออฟไลน์ถูกวัดผลกับภาพถ่ายโรคพืชจากแปลงจริง (ชุด PlantDoc ซึ่งเป็นภาพถ่ายในสภาพจริง
ไม่ใช่ภาพในห้องปฏิบัติการ) โดยใช้สองคลาสที่ตรงกับกลุ่มอาการที่ระบบแยกได้

| คลาสในชุดข้อมูล | เทียบกับกลุ่มอาการในระบบ |
|---|---|
| Squash Powdery mildew leaf | ราแป้ง (เชื้อ *Podosphaera xanthii* กลุ่มเดียวกับราแป้งแตงโม) |
| Tomato / Potato early blight | กลุ่มโรคใบจุดจากเชื้อรา |

วิธีวัดที่ใช้ และเหตุผล

1. **แยกชุดปรับกฎกับชุดตรวจสอบ** ปรับน้ำหนักด้วยภาพลำดับ 0-29 แล้ววัดผลจริงด้วยภาพลำดับ 40-79
   ซึ่งไม่เคยถูกใช้ตอนปรับ เพื่อไม่ให้ตัวเลขเกิดจากการปรับจนเข้ากับภาพชุดเดียว
   (ผลทั้งสองชุดใกล้เคียงกัน จึงเชื่อได้ว่าไม่ได้ปรับจนเกินพอดี)
2. **ดูค่ากลางของคุณลักษณะแยกตามคลาส** เพื่อหาว่าอะไรแยกกลุ่มได้จริง พบว่าสิ่งที่แยกได้ดีที่สุด
   ไม่ใช่ค่าสัมบูรณ์ แต่เป็นสัดส่วนระหว่างหลักฐาน คือคราบซีดสว่างเทียบกับใบเหลือง
   ซึ่งต่างกันราว 16 เท่าระหว่างราแป้งกับโรคใบจุด การใช้สัดส่วนยังทนต่อความต่าง
   ของแสงและระยะถ่ายภาพได้ดีกว่าเกณฑ์ตายตัว
3. **ตรวจว่าทายผิดเป็นอะไร** เพื่อหาสาเหตุที่แท้จริง ไม่ใช่แค่ปรับตัวเลขให้คะแนนสูงขึ้น

ข้อค้นพบสำคัญ: เดิมดินและเงาในภาพถ่ายจากแปลงถูกนับเป็นจุดแผล (นับได้ถึง 103 จุดในภาพเดียว)
ทำให้ภาพราแป้งถูกวินิจฉัยเป็นโรคใบจุดเกือบทุกภาพ ทายถูกอันดับหนึ่ง 0% ทั้งที่ทดสอบกับ
ภาพสังเคราะห์แล้วผ่าน เพราะภาพสังเคราะห์ไม่มีพื้นหลัง จึงเพิ่มขั้นตอนแยกบริเวณใบออกจาก
พื้นหลังก่อนวิเคราะห์ และคิดเปอร์เซ็นต์เทียบกับพื้นที่ใบแทนทั้งภาพ

ผลหลังแก้ไข (ชุดตรวจสอบที่ไม่เคยใช้ปรับกฎ): โรคใบจุด 82.5% ราแป้ง 47.5% เฉลี่ยประมาณ 65%
ทำซ้ำได้ด้วย `python3 scripts/eval_offline.py <ชุดภาพ> --mapping map.json --limit 40 --offset 40`

ราแป้งยังทายถูกน้อยกว่าเพราะภาพจำนวนหนึ่งมีทั้งคราบขาวและเนื้อใบตายปนกัน
ซึ่งแยกด้วยสีเพียงอย่างเดียวไม่ได้จริง ๆ กรณีแบบนี้คือเหตุผลที่โหมดหลักของระบบ
ควรเป็นการวิเคราะห์ด้วยโมเดล AI และเหตุผลที่โหมดออฟไลน์จำกัดความมั่นใจไว้ไม่เกิน 45%
