## การไหลของข้อมูลเมื่อวิเคราะห์ภาพ

1. **รับภาพ** — `diagnose.prepare_image()` ตรวจชนิดไฟล์และขนาด แปลงเป็น RGB
   ย่อด้านยาวสุดเหลือ 1400 px (ตั้งค่าได้) แล้วเข้ารหัสเป็น JPEG base64
   การย่อช่วยลดค่าใช้จ่ายโทเคนและเวลาตอบสนองโดยไม่เสียรายละเอียดของแผล

2. **วิเคราะห์** — เลือกเครื่องมือตามการตั้งค่า
   - มี `ANTHROPIC_API_KEY`: เรียก `llm.analyze_image()` ซึ่งส่งภาพพร้อม
     **แคตตาล็อกรหัสโรคทั้ง 48 รายการ** และบังคับรูปแบบผลลัพธ์ด้วย
     `output_config.format` แบบ JSON schema ทำให้ได้ JSON ที่ตรวจสอบได้เสมอ
   - ไม่มี key หรือเรียกไม่สำเร็จ: ถอยไปใช้ `vision_offline.analyze_offline()`
     ซึ่งวิเคราะห์สีในปริภูมิ HSV และหาก้อนแผลด้วย connected components
     แล้วให้คะแนนตามโปรไฟล์ของกลุ่มอาการ โดยจำกัดความมั่นใจไม่เกิน 45%

3. **ผสมผลจากโมเดลที่เทรนเอง** (ถ้ามี) — `local_model.predict()` คืนความน่าจะเป็นรายคลาส
   ถ้าตรงกับผลหลักจะเพิ่มความมั่นใจ ถ้าไม่ตรงและความมั่นใจสูงพอจะเพิ่มเป็นตัวเลือกใหม่
   พร้อมหมายเหตุว่ายังไม่ได้รับการยืนยันจากผลหลัก

4. **ตรวจสอบกับคลังความรู้** — `_normalize_candidates()` ตรวจว่ารหัสโรคที่โมเดลตอบมี
   อยู่จริงหรือไม่ ถ้าไม่มีจะพยายามจับคู่จากชื่อไทย และจำกัดค่าความมั่นใจให้อยู่ในช่วง 0-100

5. **ประกอบแผนการจัดการ** — `knowledge.treatment_plan()` ดึงอัตรายา ระยะพ่นซ้ำ
   กลุ่ม FRAC/IRAC ระยะเก็บเกี่ยวปลอดภัย ความเป็นพิษต่อผึ้ง ชีวภัณฑ์ การจัดการแปลง
   คำแนะนำปุ๋ย และจุดแยกจากโรคที่คล้ายกัน **จากไฟล์ JSON ทั้งหมด**

6. **เพิ่มคำเตือนตามบริบท** — `_confidence_guidance()` เตือนเมื่อความมั่นใจต่ำ
   เมื่อมีสองสาเหตุที่คะแนนใกล้กัน และเมื่อสาเหตุที่สงสัยไม่ใช่โรคติดเชื้อ
   (ซึ่งการพ่นยาฆ่าเชื้อจะไม่ช่วย)

## ทำไมต้องแยก "ระบุโรค" ออกจาก "สั่งยา"

โมเดลภาษามีโอกาสสร้างตัวเลขที่ดูสมเหตุสมผลแต่ไม่ถูกต้อง ซึ่งในบริบทการเกษตรหมายถึง
พืชเสียหาย สารตกค้างเกินมาตรฐาน หรืออันตรายต่อผู้ใช้ ระบบจึงออกแบบให้

- โมเดลเลือกได้เพียง `disease_id` จากรายการปิดที่กำหนดไว้
- คำสั่งระบบห้ามโมเดลระบุชื่อสารพร้อมอัตราใน `immediate_actions` โดยตรง
- ข้อมูลยา ปุ๋ย และอัตราทั้งหมดมาจาก `data/pesticides.json` และ `data/fertilizers.json`
  ซึ่งผ่านการตรวจด้วย `scripts/validate_data.py` และอยู่ภายใต้การควบคุมเวอร์ชันใน git

ผลคือเมื่อข้อมูลยาผิด เราแก้ที่ไฟล์เดียวและตรวจสอบย้อนหลังได้ ไม่ต้องแก้ที่พรอมต์

## การค้นคืนภาษาไทย

ภาษาไทยไม่เว้นวรรคระหว่างคำ การตัดคำด้วยช่องว่างจึงใช้ไม่ได้ และการใช้ไลบรารีตัดคำ
เพิ่ม dependency ที่หนักโดยไม่จำเป็น `app/retrieval.py` จึงใช้

- **character n-gram (2-3 ตัวอักษร)** สำหรับข้อความภาษาไทย
- **การตัดคำตามช่องว่าง** สำหรับอักษรละตินและตัวเลข (ชื่อสารภาษาอังกฤษ ตัวเลขอัตรา)
- **BM25** พร้อมการตัดคำที่พบบ่อยเกินไป (การ ที่ ของ และ ...) ออกจากดัชนี
- **โบนัสเมื่อชื่อหลักของเอกสารปรากฏตรงตัวในคำถาม** เพื่อให้การถามถึงสารเดี่ยวอย่าง
  "แมนโคเซบ" ไม่ถูกแย่งอันดับโดยสูตรผสมที่มีชื่อนั้นอยู่ด้วย

วิธีนี้ให้ผลดีพอสำหรับคลังความรู้ขนาดนี้ (ประมาณ 190 เอกสาร) โดยไม่ต้องใช้ embedding
หรือฐานข้อมูลเวกเตอร์ และทำงานได้ทันทีโดยไม่ต้องเชื่อมต่ออินเทอร์เน็ต

## การเรียกใช้โมเดล

| ส่วน | การตั้งค่า | เหตุผล |
|---|---|---|
| วิเคราะห์ภาพ | `output_config.format` เป็น JSON schema, effort `high` | ต้องการผลที่ตรวจสอบได้และความแม่นยำสูงสุด |
| แชท | streaming, effort `medium` | ผู้ใช้รออ่านอยู่ตรงหน้า จึงเน้นให้ขึ้นคำตอบเร็ว |
| ทั้งสองส่วน | `cache_control` บน system prompt | system prompt และแคตตาล็อกโรคยาวและคงที่ การแคชช่วยลดค่าใช้จ่ายและเวลา |
| ทั้งสองส่วน | server-side fallback | เมื่อคำขอถูกปฏิเสธโดยตัวกรองความปลอดภัย ระบบยังตอบผู้ใช้ได้ |
| ทั้งสองส่วน | ตรวจ `stop_reason == "refusal"` ก่อนอ่านเนื้อหา | ป้องกันการอ่านผลที่ไม่มีอยู่จริง |

ทุกการเรียกมีทางถอยเสมอ: ถ้าโมเดลเรียกไม่ได้ ระบบจะใช้โหมดออฟไลน์และแจ้งผู้ใช้
ว่ากำลังใช้โหมดใด แทนที่จะแสดงข้อผิดพลาดเปล่า ๆ

## การขยายระบบ

- **เพิ่มพืชชนิดอื่น** — เพิ่มไฟล์ใน `data/diseases/` และปรับ `DISEASE_FILES` ใน
  `app/knowledge.py` ส่วนที่เหลือทำงานต่อได้ทันทีเพราะแคตตาล็อกสร้างจากข้อมูลจริง
- **เพิ่มภาษา** — เพิ่มฟิลด์ชื่อและคำอธิบายในไฟล์ JSON แล้วปรับ system prompt
- **เก็บประวัติการวินิจฉัย** — เพิ่มชั้นฐานข้อมูลที่ `app/main.py` ตรงหลังการเรียก
  `diagnose()` โครงสร้างผลลัพธ์เป็น JSON อยู่แล้วจึงบันทึกได้ทันที
- **ใช้งานแบบออฟไลน์เต็มรูปแบบ** — เทรนโมเดล ONNX ด้วย `scripts/train_model.py`
  แล้วตั้งค่า `MELON_ONNX_MODEL` ระบบจะใช้โมเดลนั้นร่วมกับคลังความรู้โดยไม่ต้องต่ออินเทอร์เน็ต
